Frontend da JOIA

Como o terminal, as mensagens, o caderno e a comunicação com o PHP foram implementados.

Estrutura da tela

.app contém dois elementos: a barra lateral de ações e o terminal. O terminal é dividido em cabeçalho, saída rolável e rodapé com o campo de entrada.

HTML principal
<div class="app">
  <aside class="sidebar">...</aside>
  <main class="terminal">
    <header class="terminal-header">...</header>
    <section id="output" class="output">...</section>
    <footer class="terminal-footer">...</footer>
  </main>
</div>
Responsividade real da JOIA: abaixo de 700 px, as mensagens passam a ocupar até 95% da largura, recebem menos espaço interno e fonte menor. O restante do terminal utiliza clamp(), Grid e Flexbox para se adaptar sem trocar o fluxo da conversa.

As variáveis concentram cores, transparência, sombra e raio. .app cria uma coluna de 80 px para a barra e outra fluida para o terminal.

Criação das mensagens

renderMessage() remove as boas-vindas, cria o contêiner, insere o rótulo e usa createTextNode. Assim, o texto recebido não é interpretado como HTML.

JavaScript
function renderMessage(text, sender){
  document.getElementById("welcome")?.remove();
  const div = document.createElement("div");
  div.className = "msg " + sender;
  const label = document.createElement("b");
  label.textContent = sender === "user" ? "Você: " : "JOIA: ";
  div.append(label, document.createTextNode(text));
  div.style.whiteSpace = "pre-wrap";
  output.appendChild(div);
  output.scrollTop = output.scrollHeight;
}

showThinking() adiciona a mensagem animada enquanto o servidor trabalha. renderTypedMessage() remove esse indicador, revela a resposta em aproximadamente 80 etapas, conserva a última resposta e, quando o backend retorna download, cria o botão do PDF.

Envio ao backend

sendMsg() ignora texto vazio, bloqueia o campo para impedir envios simultâneos e envia JSON. Primeiro lê a resposta como texto; só depois tenta convertê-la, produzindo uma mensagem compreensível quando o PHP retorna conteúdo inválido.

Requisição fetch
const res = await fetch("teste_openai.php", {
  method: "POST",
  headers: {"Content-Type":"application/json"},
  body: JSON.stringify({
    mensagem: msg,
    conversation_id: conversationId
  })
});
Tratamento da resposta
const responseText = await res.text();
const data = responseText ? JSON.parse(responseText) : null;
if (!res.ok) {
  throw new Error(data.erro || data.resposta);
}
await renderTypedMessage(data.resposta, data.download || "");

Identificador e eventos

Um UUID fica em sessionStorage, portanto sobrevive a recargas na mesma aba. Enter chama sendMsg(); os quebra-gelos apenas preenchem o campo; uma nova conversa pede reset ao PHP e remove o UUID.

Identificador da conversa
const conversationId = sessionStorage.getItem("joia_conversation_id")
  || crypto.randomUUID();
sessionStorage.setItem("joia_conversation_id", conversationId);
Eventos principais
userInput.addEventListener("keydown", event => {
  if (event.key === "Enter") sendMsg();
});
document.querySelectorAll(".icebreaker").forEach(button =>
  button.addEventListener("click", () => {
    userInput.value = button.textContent;
    userInput.focus();
  })
);

Leitura confortável, avatar e voz

Ao iniciar uma resposta, a interface posiciona apenas o começo da nova mensagem e não força mais a rolagem durante a digitação. Assim, o estudante controla o avanço conforme lê. O painel opcional de presença carrega um avatar 3D procedural empacotado localmente somente depois da ativação. Como geometria, materiais e animações fazem parte do módulo JavaScript, não há download de GLB nem dependência de repositórios externos para exibir o personagem. A JOIA apresenta uma única voz em português e escolhe automaticamente a alternativa de maior qualidade disponível no dispositivo, priorizando vozes online da Microsoft e do Google. Avatar e leitura automática ficam em localStorage; o chat continua funcionando se WebGL, a voz, a rede ou uma dependência visual estiver indisponível.

Caderno de anotações

As notas pertencem ao navegador, não ao perfil salvo no servidor. saveNotes() escreve em localStorage; os outros botões abrem o painel, anexam a última resposta, baixam um Blob de texto ou limpam o conteúdo com confirmação.

Persistência local
function saveNotes(){
  localStorage.setItem("joia_notes", notesInput.value);
  saveStatus.textContent = "Anotações salvas agora ✓";
}
Download em TXT
const link = document.createElement("a");
link.href = URL.createObjectURL(new Blob(
  [notesInput.value], {type:"text/plain;charset=utf-8"}
));
link.download = "anotacoes-joia.txt";
link.click();
