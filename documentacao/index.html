COMECE AQUI

Visão geral

A JOIA é uma assistente educacional em português. O navegador apresenta um terminal de conversa e um caderno local; o servidor PHP conduz o cadastro, consulta o modelo de linguagem, aplica limites pedagógicos, conserva o histórico individual e produz relatórios para o docente.

01

Aprender

Orienta por perguntas, pistas e reflexão, em vez de simplesmente entregar soluções.

02

Acompanhar

Registra perfil e interações para preservar a continuidade da jornada.

03

Avaliar

Organiza evidências em relatório pedagógico e PDF para uso docente.

Para leigos: “frontend” é a tela vista pelo usuário; “backend” é o código executado no servidor; “API” é o acordo de mensagens entre esses dois lados.

AMBIENTE

Instalação e configuração

Pré-requisitos

  • Servidor web com PHP 8 ou superior, sessões e extensão cURL.
  • HTTPS válido e saída de rede para a API da OpenAI.
  • Permissão de escrita em memoria/.
  • Uma chave de API armazenada no ambiente ou em configuração fora da raiz pública.

1. Teste local sem chamar a IA

Terminal
php -S 127.0.0.1:8080
# abra http://127.0.0.1:8080

2. Configure o segredo

Prefira a variável de ambiente. A chave nunca deve entrar no HTML, Git, print, log ou wiki.

Exemplo conceitual
export OPENAI_API_KEY="sua-chave-no-servidor"
php -S 127.0.0.1:8080
Atenção: o backend também aceita config.local.php dois diretórios acima da pasta JOIA. Use o exemplo fornecido, mantenha o arquivo fora da web e aplique permissões mínimas.

SERVIDOR

API PHP

O endpoint aceita POST JSON para conversar/reiniciar e GET somente para um PDF temporário já autorizado. Todas as respostas do chat são JSON UTF-8 e usam Cache-Control: no-store.

StatusSignificadoAção
200Operação concluída.Exibir resposta.
403Acesso docente não confirmado.Não insistir; conferir credencial no servidor.
405Método HTTP inadequado.Use POST para mensagens.
422Mensagem ou conversa inválida.Corrigir a entrada.
502Falha de configuração, dados ou serviço externo.Consultar logs do servidor sem expô-los ao público.

curl -i -X POST http://127.0.0.1:8080/teste_openai.php \
  -H 'Content-Type: application/json' \
  -d '{"mensagem":"","conversation_id":"teste-local"}'
REGRAS DE NEGÓCIO

Fluxos e métodos do backend

Inicialização e respostas

Os manipuladores globais convertem falhas fatais/exceções em JSON genérico. respond() centraliza status e serialização; normalize() padroniza texto para comparações tolerantes.

Cadastro

conversation() cria o estado da sessão. onboardingValue() valida cada dado e onboardingReply() solicita, em sequência, nome, turma/curso e instituição. Ao final, um ID aleatório associa a sessão à memória criada.

Memória

memoryDirectory(), memoryPath(), loadMemory() e saveMemory() isolam leitura/escrita. O ID deve ter 32 caracteres hexadecimais e a gravação usa bloqueio exclusivo.

Orientação pedagógica

codeLineCount() estima código na resposta; recentCodeWasGiven() olha a janela recente; enforcePedagogicalCodeLimit() pede nova resposta quando a IA excede a regra.

Relatórios

allStudents() ordena cadastros, findStudent() resolve a seleção, reportFor() produz a análise e as funções pdf* fazem paginação, codificação e geração do PDF A4.

INTELIGÊNCIA ARTIFICIAL

Modelo e parâmetros

A versão documentada usa gpt-4o-mini pelo endpoint de Chat Completions. callOpenAI() adiciona as instruções do projeto, envia o histórico e lê o conteúdo da primeira escolha.

0,35Temperatura: respostas mais consistentes.
900Máximo padrão de tokens de saída.
12Itens recentes enviados como contexto.

Trocar o modelo com responsabilidade

teste_openai.php
const OPENAI_MODEL = 'nome-do-modelo-validado';

Antes de publicar, confirme disponibilidade na sua conta, compatibilidade do endpoint e dos parâmetros, custo, latência, qualidade pedagógica e tratamento de dados. Modelos e APIs evoluem: valide sempre na documentação oficial atual.

Não documentado de propósito: conteúdo integral dos prompts internos, credenciais, hashes, gatilhos da área docente e dados dos estudantes. Essa omissão protege o sistema e seus usuários.
DADOS

Memória, sessões e PDF

A sessão PHP guarda o estágio do cadastro, vínculo temporário e relatórios disponíveis. A persistência longa fica em JSON com versão do esquema, ID aleatório, perfil, datas e histórico alternado entre usuário e assistente.

Estrutura ilustrativa (dados fictícios)
{
  "schema_version": 2,
  "id": "identificador-aleatorio",
  "profile": { "full_name": "Pessoa Exemplo", "class": "Turma A" },
  "created_at": "data-em-UTC",
  "history": []
}

O PDF é montado sem biblioteca externa, usa fontes Type 1, converte texto para WinAnsi, quebra parágrafos e cria páginas conforme a altura utilizada. O link depende da sessão e de uma chave aleatória temporária.

ANTES DE PUBLICAR

Segurança e privacidade

  • Segredos: mantenha a chave somente no servidor, rotacione se houver suspeita de vazamento.
  • Dados pessoais: restrinja acesso e backup de memoria/; defina retenção e base legal com a instituição.
  • Logs: registre o necessário para diagnóstico, nunca prompts completos, chaves ou dados sensíveis.
  • Área docente: troque qualquer credencial padrão antes de publicar e prefira autenticação robusta, rate limit e auditoria.
  • Uploads: o arquivo legado exige validação MIME, nomes aleatórios fortes, limite de tamanho e armazenamento fora da raiz pública antes de ser habilitado.
  • Dependências: fixe versões, mantenha integridade SRI e revise CDNs periodicamente.
  • Erros: mensagens públicas devem ser genéricas; detalhes ficam somente no log protegido.
Nunca copie para esta wiki: chaves reais, tokens, hashes de acesso, caminhos privados, memórias de alunos ou o texto integral das instruções internas.
MANUTENÇÃO

Diagnóstico e testes

Abra as ferramentas do navegador, veja a requisição POST e o status. Confirme PHP cURL, chave, cota, saída HTTPS, configuração e log protegido do servidor.

Verifique se memoria/ existe e se o usuário do servidor possui escrita, sem conceder permissão pública ampla.

Teste em 320, 576, 768, 992 e 1200 px. Procure larguras fixas, conteúdo sem quebra e elementos que ignoram min-width: 0.
Checklist de terminal
php -l teste_openai.php
php -l upload_temp.php
git status --short
# depois: teste conversa, cadastro, notas, reset e PDF no navegador
DEPLOY

Publicação e rotina de mudança

  1. Crie uma cópia/branch.Evite editar produção diretamente.
  2. Faça uma mudança pequena.Frontend, backend ou instruções — uma intenção clara.
  3. Valide sintaxe e fluxos.Inclua celular, desktop, erro de API e acessibilidade por teclado.
  4. Revise privacidade.Confira o diff procurando segredos e dados pessoais.
  5. Atualize versão e wiki.Mantenha aplicação, documentação e histórico coerentes.
  6. Publique e monitore.Faça backup seguro e acompanhe erros sem expor detalhes.

Em hospedagem sob /joia/, preserve os caminhos relativos: a aplicação fica em /joia/ e esta documentação em /joia/documentacao/.
