Segurança e diagnóstico

Proteções já presentes, pontos de atenção e verificações operacionais da JOIA.

Proteções implementadas

  • Chave OpenAI procurada em variável de ambiente ou arquivo fora da pasta pública.
  • Erros de inicialização são genéricos para o navegador e detalhados somente no log.
  • ID persistente do estudante usa aleatoriedade criptográfica e formato restrito.
  • Gravação de memória utiliza bloqueio exclusivo.
  • Mensagens são renderizadas como texto, reduzindo risco de HTML injetado.
  • Respostas JSON e PDFs usam no-store ou vínculo com sessão.
  • Acesso docente é protegido; seus detalhes não são publicados aqui.

Configuração da API

A opção preferencial é OPENAI_API_KEY no ambiente do processo PHP. Como alternativa, o sistema procura config.local.php dois diretórios acima da JOIA.

Modelo de configuração
&lt;?php
return [
  'OPENAI_API_KEY' => 'definida-somente-no-servidor'
];
Nunca publique: chave real, credencial docente, hashes de acesso, sessões, memória de alunos ou instruções internas completas.

Validações de entrada

O ID da conversa aceita letras, números e hífen e possui até 80 caracteres. A mensagem precisa existir e respeitar 4.000 caracteres. O ID do estudante aceita exatamente 32 caracteres hexadecimais. O método do chat é POST.

Validação de mensagem
$messageLength = function_exists('mb_strlen')
  ? mb_strlen($message, 'UTF-8') : strlen($message);
if ($message === '' || $messageLength > MAX_MESSAGE_LENGTH) {
  respond(['erro' => 'Digite uma mensagem válida.'], 422);
}

Upload temporário legado

upload_temp.php permite extensões de imagem/áudio, move o arquivo e remove itens com mais de 30 minutos. Ele não está conectado ao terminal atual. Antes de habilitá-lo, é necessário validar MIME real, limitar tamanho, gerar nome criptograficamente aleatório, impedir execução e armazenar fora da raiz pública.

Não recomendado em produção como está: a implementação usa permissão ampla de diretório, confia na extensão e monta URL com o host da requisição.

Diagnóstico por sintoma

Verifique o log PHP, sintaxe, extensão cURL, chave e se o servidor consegue sair por HTTPS.

Confirme existência e permissão mínima de escrita em memoria/. Não use permissão pública ampla.

Confira chave, cota, modelo disponível, endpoint e o status registrado no log protegido.

Verificações antes da publicação

Lint e inspeção
php -l teste_openai.php
php -l upload_temp.php
git diff --check
git status --short
  • Testar cadastro completo e conversa em uma sessão nova.
  • Testar erro controlado sem chave e indisponibilidade externa.
  • Testar notas, download TXT, reset e PDF.
  • Verificar celular, teclado e leitor de tela.
  • Revisar o diff procurando segredos e dados pessoais.
  • Definir retenção, backup e acesso institucional às memórias.
